# Gül Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the radar chart on Muhasebe › Özet with the approved 3D rose whose five petals open with today's progress.

**Architecture:** Progress is computed in Kotlin by pure, unit-tested functions (`GulLogic.kt`). The rose is the approved three.js prototype, trimmed to a page in `assets/gul/`. A Compose card hosts it in a `WebView`, serves the assets itself through `shouldInterceptRequest` (no new library), pushes the five petal values with `evaluateJavascript`, and turns horizontal drags into rotation from a Compose overlay so vertical page scrolling keeps working.

**Tech Stack:** Kotlin, Jetpack Compose, Android `WebView`, three.js 0.170.0 (vendored JS files), JUnit 4.

**Spec:** `docs/superpowers/specs/2026-11-04-gul-design.md`. The visual reference is `design/gul/gul-3d.html`.

## Global Constraints

- No new Gradle dependency (`AGENTS.md`). three.js goes in as asset files, not a library.
- minSdk 31. The phone is a Xiaomi on Android 16. The app must work offline.
- The look matches `design/gul/gul-3d.html`: night scene, kızıl rose, `OPEN_MAX = .6`, muted closed petals, glow on finished petals, gold heart light and dust on completion.
- Petal order and names: **Namaz, Vaktinde, Sayfa, Kaza, Zikir**, at the prototype's five angles (`-(i*72+18)°`). Zikir sits in the old "Hedef" slot.
- Until the zikir module exists, "all done" means **the first four petals**. This one rule drives the inner bud (`min` of the four), hiding the labels, and the celebration.
- The day is the prayer day, **imsak to imsak**. The same rule is used for `logPages` and `logKaza`.
- No zoom. Drag rotates. When nobody touches it, the rose slowly auto-rotates at the prototype speed.
- Build: `JAVA_HOME=~/jdk/jdk-17.0.21.0.2+1 ./gradlew testDebugUnitTest assembleDebug` from the repo root.

## Review Focus

1. Yatsı marked at 01:00: the rose still shows the previous day and counts that yatsı. It starts again from a bud at imsak. *(Task 1 test `prayerDayBeforeImsakIsYesterday`.)*
2. No reading goal (`readGoal = 0`), no kaza debt, or `kazaRate = 0`: the petal shows fully open, not 0 and never NaN. *(Task 1 tests `zeroGoalCountsAsDone`, `noKazaDebtIsFullPetal`.)*
3. A prayer that was marked and then unmarked lowers both Namaz and Vaktinde, even if a `prayedAt` time is still stored. *(Task 1 test `unmarkedPrayerDoesNotCount`.)*
4. Switching tabs and returning, or recreating the WebView, never leaves the rose stuck as a closed bud while progress exists. The values are pushed again when the page finishes loading. *(Task 4, step "reload check".)*
5. A vertical swipe that starts on the rose scrolls the Özet page. A horizontal drag rotates the rose. *(Task 4, step "gesture check".)*

### Task 1: Progress logic

**Files:**
- Create: `app/src/main/java/com/namazim/GulLogic.kt`
- Test: `app/src/test/java/com/namazim/GulTest.kt`

**Interfaces:**
- Produces:
  - `data class Petal(val name: String, val progress: Float, val label: String, val counts: Boolean)`
  - `fun prayerDayOf(today: LocalDate, now: Long, imsakToday: Long): LocalDate`. Returns yesterday when `now < imsakToday`, otherwise today.
  - `fun inFirstThird(slot: Slot, at: Long?): Boolean`. True when `at` is in `[slot.start, slot.start + (slot.end - slot.start) / 3)`.
  - `fun ratio(done: Int, goal: Int): Float`. Returns `1f` when `goal <= 0`, otherwise `done/goal` clamped to `0..1`.
  - `fun gulPetals(slots: List<Slot>, prayed: Set<String>, prayedAt: (String) -> Long?, pagesToday: Int, readGoal: Int, kazaToday: Int, kazaRate: Int, kazaOwed: Int): List<Petal>`. Returns the 5 petals in the global order. Labels: Namaz `"3/5"`, Vaktinde `"2/5"`, Sayfa `"$pagesToday/$readGoal"`, Kaza `"$kazaToday/$kazaRate"`, Zikir `"yakında"`. Kaza progress is `1f` when `kazaOwed == 0`. Zikir is `progress = 0f, counts = false`. The other four have `counts = true`.

- [ ] **Step 1: Write the failing tests in `GulTest.kt`**

Use a five-slot fixture built by hand (`Slot(Vakit.X, day, start, end, end)`, each window 3 hours, starting at 0, 3h, 6h…). Tests:

```kotlin
@Test fun prayerDayBeforeImsakIsYesterday() {
    val d = LocalDate.of(2026, 11, 5)
    assertEquals(d.minusDays(1), prayerDayOf(d, now = 1_000, imsakToday = 2_000))
    assertEquals(d, prayerDayOf(d, now = 2_000, imsakToday = 2_000))
}
@Test fun firstThirdBoundaries() {          // window 0..90 min → first third is [0, 30)
    val s = Slot(Vakit.OGLE, day, 0, 90 * min, 90 * min)
    assertTrue(inFirstThird(s, 0)); assertTrue(inFirstThird(s, 30 * min - 1))
    assertFalse(inFirstThird(s, 30 * min)); assertFalse(inFirstThird(s, null)); assertFalse(inFirstThird(s, -1))
}
@Test fun zeroGoalCountsAsDone() { assertEquals(1f, ratio(0, 0)); assertEquals(1f, ratio(5, 3)); assertEquals(.5f, ratio(1, 2)) }
@Test fun petalsOrderAndLabels() {
    // 3 prayed, 2 of them in the first third; 1 page of 3; 1 kaza of 2, debt 40
    val p = gulPetals(slots, prayed = setOf(k0, k1, k2), prayedAt = mapOf(k0 to early0, k1 to early1, k2 to late2)::get,
        pagesToday = 1, readGoal = 3, kazaToday = 1, kazaRate = 2, kazaOwed = 40)
    assertEquals(listOf("Namaz", "Vaktinde", "Sayfa", "Kaza", "Zikir"), p.map { it.name })
    assertEquals(listOf(.6f, .4f, 1f / 3, .5f, 0f), p.map { it.progress })
    assertEquals(listOf("3/5", "2/5", "1/3", "1/2", "yakında"), p.map { it.label })
    assertEquals(listOf(true, true, true, true, false), p.map { it.counts })
}
@Test fun noKazaDebtIsFullPetal() { assertEquals(1f, gulPetals(slots, emptySet(), { null }, 0, 3, 0, 2, kazaOwed = 0)[3].progress) }
@Test fun unmarkedPrayerDoesNotCount() {
    val p = gulPetals(slots, prayed = emptySet(), prayedAt = { early0 }, 0, 3, 0, 2, 40)
    assertEquals(0f, p[0].progress); assertEquals(0f, p[1].progress)
}
```

- [ ] **Step 1: Write `GulCard` in `GulView.kt`.** It is an `AndroidView` with a `WebView`:
  - Settings: `javaScriptEnabled = true`, `setBackgroundColor(0xFF121D33.toInt())`, height `300.dp`.
  - It loads `https://gul.local/gul.html`. `shouldInterceptRequest` answers every `gul.local` request from `assets/gul/<path>`, with the mime type taken from the file extension (`.js` → `text/javascript`, `.html` → `text/html`). Any other host gets an empty 404 response, so nothing goes online.
  - `onPageFinished` pushes the current petals.
  - When `petals` changes, push again: `evaluateJavascript("gul.set(${json})", null)`. Build the JSON with `org.json`.
  - On top of the WebView sits a transparent `Box` with `Modifier.pointerInput(Unit) { detectHorizontalDragGestures { _, dx -> web.evaluateJavascript("gul.spin($dx)", null) } }`. The WebView itself takes no touch input (`setOnTouchListener { _, _ -> true }`). This way vertical gestures reach the page's `verticalScroll`.
  - `onPause()` and `onResume()` follow the lifecycle through `LocalLifecycleOwner`. The view is destroyed on dispose.
